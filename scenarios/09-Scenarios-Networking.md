## سناریو ۱ (مبتدی): بررسی و تنظیم موقت یک IP آدرس با ip (سطح مبتدی)

### زمینه و چرایی
قبل از سناریوهای پیچیده VLAN/Bonding، باید ساده‌ترین کار روزمره — دیدن و تغییر موقت IP — را مسلط باشید.

### قدم‌به‌قدم

**۱. مشاهده تمام اینترفیس‌ها و IP هایشان**
```bash
ip addr show
```
🔍 **تحلیل دستور:** بدون سوییچ؛ لیست کامل اینترفیس‌ها همراه با IP، وضعیت (UP/DOWN)، و MAC Address.

**۲. مشاهده فقط یک اینترفیس خاص**
```bash
ip addr show dev eth0
```
🔍 **تحلیل دستور:** `dev eth0`: مشخص می‌کند فقط این یک دستگاه نمایش داده شود، نه همه.

**۳. افزودن یک IP موقت**
```bash
ip addr add 192.168.1.50/24 dev eth0
```
🔍 **تحلیل دستور:**
- `add`: زیردستور افزودن.
- `192.168.1.50/24`: IP همراه با CIDR prefix.
- `dev eth0`: روی کدام اینترفیس اعمال شود.

**۴. تایید افزودن**
```bash
ip addr show dev eth0
```

**۵. حذف همان IP**
```bash
ip addr del 192.168.1.50/24 dev eth0
```
🔍 **تحلیل دستور:** `del`؛ باید دقیقاً همان IP/prefix که اضافه شده بود مشخص شود تا حذف شود.

### ✅ Best Practice
تغییرات `ip addr` موقتی هستند؛ برای دائمی کردن باید از NetworkManager/netplan استفاده کرد.




##  تنظیم دائمی IP با Netplan و NetworkManager

### زمینه و چرایی
دستورات `ip addr add/del` فقط تا زمان ری‌استارت یا خاموشی سیستم معتبرند. برای اینکه یک IP آدرس به‌طور دائمی روی اینترفیس باقی بماند، باید تنظیمات را در فایل‌های کانفیگ شبکه ذخیره کنیم. ابزار **Netplan** با فایل‌های YAML کار می‌کند و پشت‌صحنه از `systemd-networkd` یا `NetworkManager` به‌عنوان رندرکننده استفاده می‌کند. در این سناریو، هم روش Netplan و هم روش مستقیم `nmcli` (خط فرمان NetworkManager) را یاد می‌گیرید.

---

### قدم‌به‌قدم (روش اول: Netplan)

#### ۱. پیدا کردن فایل کانفیگ Netplan
```bash
ls /etc/netplan/
```
🔍 **تحلیل دستور**:  
Netplan فایل‌های کانفیگ را با پسوند `.yaml` در `/etc/netplan/` ذخیره می‌کند. معمولاً نام فایل‌ها چیزی شبیه `01-netcfg.yaml` یا `50-cloud-init.yaml` است. اگر چند فایل وجود داشته باشد، ترتیب اعمال بر اساس ترتیب حروف الفبا است (اعداد اولویت را مشخص می‌کنند).

#### ۲. ویرایش فایل (با استفاده از sudo و یک ویرایشگر مثل nano)
```bash
sudo nano /etc/netplan/01-netcfg.yaml
```
🔍 **تحلیل دستور**:  
با دسترسی root فایل را باز می‌کنیم. محتوای نمونه برای یک IP استاتیک به این شکل است:

```yaml
network:
  version: 2
  ethernets:
    eth0:
      dhcp4: no
      addresses:
        - 192.168.1.50/24
      gateway4: 192.168.1.1
      nameservers:
        addresses: [8.8.8.8, 1.1.1.1]
```

- **`version: 2`**: نسخه‌ی فرمت Netplan (همیشه ۲).
- **`ethernets`**: بخش مربوط به اینترفیس‌های سیمی.
- **`eth0`**: نام اینترفیس هدف.
- **`dhcp4: no`**: غیرفعال کردن DHCP برای آدرس‌دهی دستی.
- **`addresses`**: لیست IP/prefixها (می‌توانید چند IP به یک اینترفیس بدهید).
- **`gateway4`**: آدرس دروازه‌ی پیش‌فرض.
- **`nameservers`**: DNS سرورها.



#### برسی صحیح بودن سینتکس 
```bash
sudo netplan generate
```
#### ۳. اعمال تغییرات
```bash
sudo netplan apply
```
🔍 **تحلیل دستور**:  
این دستور، فایل‌های YAML را بررسی (validation) کرده و تنظیمات را به رندرکننده‌ی پشتیبان (`networkd` یا `NetworkManager`) اعمال می‌کند. اگر خطای سینتکس در YAML وجود داشته باشد، ارور می‌دهد و تغییری اعمال نمی‌شود.

#### ۴. تایید اعمال
```bash
ip addr show dev eth0
```
🔍 **تحلیل دستور**:  
مشاهده‌ی IP جدید روی اینترفیس. همچنین می‌توانید مسیر پیش‌فرض را چک کنید:
```bash
ip route show default
```

#### ۵. تست اتصال
```bash
ping -c 4 8.8.8.8
```
🔍 **تحلیل دستور**:  
تأیید connectivity به بیرون از شبکه.

---

### قدم‌به‌قدم (روش دوم: NetworkManager با `nmcli`)

اگر سیستم شما از NetworkManager به‌عنوان رندرکننده استفاده می‌کند (یا در دسکتاپ هستید)، می‌توانید مستقیماً با `nmcli` کار کنید.

#### ۱. مشاهده اتصالات موجود
```bash
nmcli connection show
```
🔍 **تحلیل دستور**:  
لیست تمام اتصالات ذخیره‌شده (معمولاً یک اتصال به نام `eth0` یا `Wired connection 1` وجود دارد).

#### ۲. تغییر IP به‌صورت استاتیک (برای یک اتصال خاص)
```bash
sudo nmcli connection modify "eth0" ipv4.addresses 192.168.1.50/24
sudo nmcli connection modify "eth0" ipv4.gateway 192.168.1.1
sudo nmcli connection modify "eth0" ipv4.dns "8.8.8.8 1.1.1.1"
sudo nmcli connection modify "eth0" ipv4.method manual
```
🔍 **تحلیل دستورات**:  
- `modify`: تغییر پارامترهای اتصال.
- `ipv4.addresses`: آدرس IP با CIDR.
- `ipv4.gateway`: دروازه.
- `ipv4.dns`: لیست DNS (با فاصله).
- `ipv4.method manual`: یعنی استاتیک (مقابل `auto` برای DHCP).

#### ۳. اعمال تغییرات (ری‌استارت اتصال)
```bash
sudo nmcli connection down "eth0" && sudo nmcli connection up "eth0"
```
🔍 **تحلیل دستور**:  
قطع و وصل کردن اتصال برای اعمال تنظیمات جدید.

#### ۴. تایید
```bash
ip addr show dev eth0
```

## سناریو ۲ (مبتدی): تست اتصال پایه با ping و traceroute (سطح مبتدی)

### قدم‌به‌قدم

**۱. تست اتصال ساده با تعداد محدود بسته**
```bash
ping -c 4 8.8.8.8
```
🔍 **تحلیل دستور:** `-c 4`: مخفف `--count` — ارسال دقیقاً ۴ بسته و توقف خودکار؛ بدون این، `ping` بی‌نهایت ادامه می‌دهد.

**۲. مشاهده مسیر کامل بسته**
```bash
traceroute 8.8.8.8
```
🔍 **تحلیل دستور:** بدون سوییچ؛ هر خط یک هاپ میانی همراه با زمان پاسخ آن است.

**۳. تست پورت خاص یک سرویس**
```bash
nc -zv 192.168.1.10 80
```
🔍 **تحلیل دستور:**
- `-z`: مخفف `--zero-io` — فقط تست اتصال بدون ارسال داده واقعی.
- `-v`: مخفف `--verbose` — نمایش پیام موفقیت/شکست خوانا.

**۴. بررسی جدول ARP محلی**
```bash
ip neigh show
```
🔍 **تحلیل دستور:** بدون سوییچ؛ نگاشت IP به MAC که اخیراً resolve شده.

### 📌 نکته آزمون
ترتیب استاندارد عیب‌یابی: Link → IP → Gateway → Routing → DNS → Port.

## سناریو ۳: طراحی صحیح Subnetting برای سه بخش سازمانی (سطح متوسط)

### قدم‌به‌قدم

**۱. محاسبه خودکار جزئیات هر subnet**
```bash
ipcalc 10.0.0.0/21
```
🔍 **تحلیل دستور:** بدون سوییچ؛ آرگومان `IP/prefix` — محاسبه خودکار Network Address، Broadcast Address، و بازه Host قابل‌استفاده.

**۲. تخصیص بلوک دوم**
```bash
ipcalc 10.0.8.0/23
```

**۳. ساخت VLAN برای هر بخش**
```bash
ip link add link eth0 name eth0.10 type vlan id 10
```
🔍 **تحلیل دستور:**
- `link eth0`: کدام اینترفیس فیزیکی پایه.
- `name eth0.10`: نام دلخواه اینترفیس مجازی جدید.
- `type vlan id 10`: نوع دستگاه مجازی و شماره Tag.

**۴. تخصیص IP و فعال‌سازی**
```bash
ip addr add 10.0.0.1/21 dev eth0.10
ip link set eth0.10 up
```

**۵. تایید عدم همپوشانی**
```bash
ip route show
```

### 📌 نکته آزمون
محاسبات CIDR باید کاملاً مسلط باشد.

## سناریو ۴: راه‌اندازی Bridge برای ماشین‌های مجازی (سطح پیشرفته)

### قدم‌به‌قدم

**۱. ساخت Bridge**
```bash
ip link add <" br0 "> type bridge
```
🔍 **تحلیل دستور:** `type bridge`: این‌بار یک سوییچ نرم‌افزاری ساخته می‌شود، نه VLAN.

**۲. انتقال IP از فیزیکی به Bridge**
```bash
ip addr del 192.168.1.50/24 dev eth0
ip addr add 192.168.1.50/24 dev br0
```
🔍 **تحلیل دستور:** همان `del`/`add` سناریو ۱، اینجا برای انتقال IP از اینترفیس فیزیکی به دستگاه Bridge.

**۳. اضافه کردن فیزیکی به‌عنوان پورت Bridge**
```bash
ip link set <" eth0 "> master <" br0 ">
```
🔍 **تحلیل دستور:** `master br0`: به `ip link set` می‌گوید `eth0` را زیرمجموعه دستگاه `br0` قرار بده — از این لحظه `eth0` مستقیماً IP ندارد، فقط یک پورت خام است.

**۴. فعال‌سازی هر دو**
```bash
ip link set eth0 up
ip link set br0 up
```

### ✅ Best Practice
حالت Bridge برای ماشین‌های مجازی که باید IP مستقیم از شبکه فیزیکی بگیرند مناسب است.

## سناریو ۵: عیب‌یابی مشکل شبکه متناوب با mtr (سطح پیشرفته)

### قدم‌به‌قدم

**۱. تست ساده اولیه**
```bash
ping -c 10 app.internal.example.com
```

**۲. تست تکراری با گزارش نهایی**
```bash
mtr --report --report-cycles 100 app.internal.example.com
```
🔍 **تحلیل دستور:**
- `--report`: به‌جای حالت زنده تعاملی، فقط گزارش نهایی خلاصه چاپ کن.
- `--report-cycles 100`: تعداد بسته‌های تست؛ عدد بیشتر یعنی آمار قابل‌اعتمادتر برای مشکلات متناوب.

**۳. تمرکز روی مقصد از سمت خود سرور**
```bash
vmstat 2 10
```

**۴. ا capture ترافیک روی سرور مقصد**
```bash
tcpdump -i eth0 icmp -w /tmp/icmp-capture.pcap
```
🔍 **تحلیل دستور:**
- `icmp`: فیلتر فقط بسته‌های پروتکل ICMP.
- `-w`: مخفف `--write` — ذخیره در فایل باینری برای تحلیل بعدی.

**۵. تحلیل با timestamp دقیق**
```bash
tcpdump -r /tmp/icmp-capture.pcap -tttt
```
🔍 **تحلیل دستور:**
- `-r`: مخفف `--read` — خواندن از فایل ذخیره‌شده.
- `-tttt`: نمایش تاریخ و ساعت کامل برای هر بسته.

**۶. بررسی شمارنده‌های خطای کارت شبکه**
```bash
ethtool -S eth0 | grep -i "drop\|error"
```
🔍 **تحلیل دستور:** `-S`: مخفف `--statistics` — شمارنده‌های آماری سطح پایین سخت‌افزاری.

### 📌 نکته آزمون
ا `mtr --report-cycles` نسبت به یک `ping` تک‌باره برای مشکلات متناوب بسیار قوی‌تر است.

## سناریو ۶: ارتقای Bonding از active-backup به LACP (سطح پیشرفته)

### قدم‌به‌قدم

**۱. بررسی وضعیت فعلی**
```bash
cat /proc/net/bonding/bond0
```
🔍 **تحلیل دستور:** بدون سوییچ؛ فایل مجازی که وضعیت کامل bond فعلی را نشان می‌دهد.

**۲. تغییر mode با nmcli**
```bash
nmcli connection modify bond0 bond.options "mode=802.3ad,miimon=100,lacp_rate=fast"
```
🔍 **تحلیل دستور:**
- `connection modify`: ویرایش یک اتصال موجود.
- `bond.options`: پراپرتی مقادیر داخلی bonding.
- مقدار: `mode=802.3ad` نوع LACP، `miimon=100` فاصله بررسی سلامت لینک، `lacp_rate=fast` فرکانس بالای پیام‌های کنترلی.

**۳. اعمال با پایین/بالا بردن اتصال**
```bash
nmcli connection down bond0
nmcli connection up bond0
```
🔍 **تحلیل دستور:** بعد از `modify`، باید اتصال یک‌بار خاموش/روشن شود تا تغییرات mode اعمال شوند.

**۴. تایید مذاکره موفق LACP**
```bash
cat /proc/net/bonding/bond0
```

**۵. تست پهنای باند تجمیعی**
```bash
iperf3 -c target-ip -P 4
```
🔍 **تحلیل دستور:** `-c`: حالت کلاینت؛ `-P 4`: مخفف `--parallel` — ساخت ۴ جریان TCP هم‌زمان برای تست توزیع بار.

### ⚠️ نکته عملیاتی حیاتی
تغییر به LACP بدون هماهنگی با تیم سوییچ معمولاً باعث قطعی کامل می‌شود.

## جمع‌بندی مهارت‌های این بخش

- کار پایه با `ip addr` برای افزودن/حذف موقت IP
- تست پایه اتصال با `ping`/`traceroute`/`nc -z`
- محاسبه دقیق Subnetting با `ipcalc` و ساخت VLAN
- راه‌اندازی Bridge با تحلیل دقیق `master` در `ip link set`
- عیب‌یابی عمیق مشکلات متناوب با `mtr --report-cycles` و `tcpdump`
- ارتقای Bonding به LACP با تحلیل کامل پارامترهای `nmcli`
