# بخش ۱۲ب:  امنیت — SSH Hardening، VPN و Fail2ban

> این فایل ضمیمه بخش ۱۲ (Security) است و سه موضوع حیاتی را پوشش می‌دهد: سخت‌سازی دسترسی SSH، شبکه خصوصی مجازی (VPN)، و محافظت خودکار در برابر Brute-force.
> پیش‌نیاز مفهومی: بخش ۹ (Networking) و بخش ۱۲ (فایروال nftables/firewalld).

---

## ۱۲ب.۱ چرا SSH نیازمند سخت‌سازی جداگانه است

ا SSH معمولاً **تنها درِ ورودی مدیریتی** یک سرور Remote است — اگر این در به‌درستی محافظت نشود، کل سرور در معرض خطر است. برخلاف یک سرویس وب که محتوایش عمومی است، SSH باید فقط برای افراد مجاز، با بالاترین سطح ممکن از احراز هویت، در دسترس باشد.

## ۱۲ب.۲ تنظیمات کلیدی sshd_config

```
Port 2222
PermitRootLogin no
PasswordAuthentication no
PubkeyAuthentication yes
AllowUsers alice bob
MaxAuthTries 3
ClientAliveInterval 300
ClientAliveCountMax 2
X11Forwarding no
```

**`PermitRootLogin no`**:

 هرگز نباید اجازه ورود مستقیم root از طریق SSH داده شود — همان اصل بخش ۱۱ (استفاده از `sudo` به‌جای لاگین مستقیم root) اینجا در سطح شبکه اعمال می‌شود؛ هر مدیر باید با حساب شخصی خودش وارد شود و سپس با `sudo` امتیاز بگیرد.

**`PasswordAuthentication no`**:

 اجبار به احراز هویت با کلید عمومی/خصوصی به‌جای رمز عبور — کلیدها در برابر Brute-force عملاً غیرقابل‌حدس‌زدن هستند، برخلاف رمزهای عبور.

**`Port 2222`**: 

تغییر پورت پیش‌فرض کاهش‌دهنده حجم اسکن‌های خودکار است (نه یک لایه امنیتی واقعی — یک مهاجم مصمم به‌راحتی پورت‌های باز را اسکن می‌کند)؛ این را **Security through Obscurity** می‌نامند و هرگز نباید به‌تنهایی به آن تکیه کرد.

```bash
sshd -t                # همیشه قبل از restart
systemctl restart sshd
```
⚠️ طبق اصل تکرارشونده در این کتابچه: قبل از restart سرویس SSH، همیشه یک نشست فعال دیگر باز نگه دارید.

## ۱۲ب.۳ احراز هویت با کلید عمومی

```bash
ssh-keygen -t ed25519 -C "alice@laptop"
ssh-copy-id -i ~/.ssh/id_ed25519.pub alice@server
```

ا `ed25519` نسبت به `rsa` سنتی، امنیت معادل یا بالاتر با کلید بسیار کوچک‌تر و سریع‌تر ارائه می‌دهد — انتخاب مدرن توصیه‌شده.


🔹 ا ssh-keygen یک جفت کلید SSH می‌سازد: کلید خصوصی (~/.ssh/id_ed25519) و کلید عمومی (~/.ssh/id_ed25519.pub).

🔹 ا -t ed25519: نوع کلید (مدرن، سریع و امن).

🔹 ا -C "alice@laptop": یک برچسب/کامنت برای شناسایی راحت‌تر کلید (مثلاً نام کاربر و دستگاه).

🔹ا ssh-copy-id کلید عمومی شما را به سرور مقصد کپی می‌کند و در فایل ~/.ssh/authorized_keys کاربر alice قرار می‌دهد.

🔹 ا -i ~/.ssh/id_ed25519.pub: مسیر کلید عمومی موردنظر.

🔹 بعد از این دستور، می‌توانید بدون وارد کردن رمز عبور به سرور SSH بزنید: ssh alice@server.

```bash
chmod 700 ~/.ssh
chmod 600 ~/.ssh/authorized_keys
```
⚠️ ا SSH با مجوزهای خیلی باز روی `~/.ssh` یا `authorized_keys` **از نظر امنیتی** اتصال را رد می‌کند (نه فقط یک هشدار) — این یک اقدام محافظتی داخلی خود SSH است.

## ۱۲ب.۴ SSH Tunneling — استفاده از SSH به‌عنوان یک VPN سبک

```bash
ssh -L 8080:localhost:80 alice@server        # Local Forward
ssh -D 1080 alice@server                       # Dynamic Forward (SOCKS Proxy)
```
در ادامه، مفهوم **SSH Tunneling** را به‌طور کامل و با جزئیات، همراه با مثال‌های عملی برای هر سه نوع اصلی (Local، Remote، Dynamic) توضیح می‌دهم.

---

## ا SSH Tunneling چیست؟

ا SSH Tunneling (یا SSH Port Forwarding) روشی است که با استفاده از یک اتصال SSH امن، ترافیک شبکه‌ای را از داخل آن عبور می‌دهیم. به این ترتیب، می‌توانیم به سرویس‌هایی دسترسی پیدا کنیم که مستقیماً از بیرون قابل دسترس نیستند، یا ترافیک خود را از یک مسیر امن عبور دهیم. به آن «VPN سبک» می‌گویند چون بدون راه‌اندازی VPN واقعی، یک تونل رمزنگاری‌شده ایجاد می‌کند.

سه نوع اصلی تونل‌زنی SSH:

| نوع | سوییچ | کاربرد اصلی |
|---|---|---|
| Local Forward | `-L` | دسترسی به سرویس روی سرور راه دور از طریق پورت محلی |
| Remote Forward | `-R` | دسترسی سرور راه دور به سرویس روی کامپیوتر محلی |
| Dynamic Forward | `-D` | ساخت یک پروکسی SOCKS برای عبور ترافیک مرورگر/برنامه |

---

## ۱. Local Forward (`-L`)

### ساختار دستور
```bash
ssh -L [پورت_محلی]:[میزبان_مقصد]:[پورت_مقصد] [کاربر]@[سرور_SSH]
```

### معنی اجزا
- `پورت_محلی`: پورتی روی کامپیوتر شما که به آن گوش داده می‌شود.
- `میزبان_مقصد`: آدرسی که از دید **سرور SSH** قابل دسترسی است (معمولاً `localhost` یا IP داخلی).
- `پورت_مقصد`: پورت سرویس روی میزبان مقصد.
- `سرور_SSH`: سروری که به آن SSH می‌زنید و تونل از آن عبور می‌کند.

### مثال ۱: دسترسی به وب‌سرور داخلی
فرض کنید سرور SSH شما `server` است و یک سرویس وب داخلی روی `192.168.1.50:80` در شبکه داخلی آن قرار دارد که از بیرون قابل دسترسی نیست. می‌خواهید از لپ‌تاپ خود به آن دسترسی داشته باشید:

```bash
ssh -L 8080:192.168.1.50:80 alice@server
```

- از این به بعد، اگر در مرورگر لپ‌تاپ خود `http://localhost:8080` را باز کنید، ترافیک به‌صورت امن از تونل SSH عبور کرده و به `192.168.1.50:80` می‌رسد.
- سرویس داخلی هرگز مستقیماً روی اینترنت باز نشده است.

### مثال ۲: دسترسی به دیتابیس روی سرور
دیتابیس MySQL روی سرور `server` فقط به `localhost` گوش می‌دهد (پورت 3306). می‌خواهید با ابزار محلی به آن وصل شوید:

```bash
ssh -L 3307:localhost:3306 alice@server
```
سپس در ابزار محلی، به `127.0.0.1:3307` وصل شوید. ترافیک از تونل SSH عبور می‌کند و به MySQL روی سرور می‌رسد.

### مثال ۳: استفاده از `-N` و `-f` برای اجرای پس‌زمینه
اگر فقط می‌خواهید تونل برقرار باشد و وارد شل نشوید:

```bash
ssh -N -f -L 8080:localhost:80 alice@server
```
- `-N`: دستور اجرا نکن (فقط تونل).
- `-f`: اجرا در پس‌زمینه.

---

## ۲. Remote Forward (`-R`)

### ساختار دستور
```bash
ssh -R [پورت_راه_دور]:[میزبان_مقصد]:[پورت_مقصد] [کاربر]@[سرور_SSH]
```

### معنی اجزا
- `پورت_راه_دور`: پورتی روی **سرور SSH** که به آن گوش داده می‌شود.
- `میزبان_مقصد`: آدرسی که از دید **کامپیوتر شما** قابل دسترسی است (معمولاً `localhost`).
- `پورت_مقصد`: پورت سرویس روی کامپیوتر شما.

### مثال: اشتراک‌گذاری سرویس محلی با سرور راه دور
فرض کنید روی لپ‌تاپ خود یک سرور وب روی پورت 3000 دارید و می‌خواهید دوستتان که به سرور `server` دسترسی دارد، آن را ببیند:

```bash
ssh -R 8000:localhost:3000 alice@server
```
- حالا روی سرور `server`، اگر کسی `http://localhost:8000` را باز کند، ترافیک از تونل SSH عبور کرده و به لپ‌تاپ شما می‌رسد.
- این برای اشتراک‌گذاری موقت یک سرویس محلی بسیار مفید است.

> نکته: به‌طور پیش‌فرض، Remote Forward فقط به `localhost` روی سرور راه دور گوش می‌دهد. برای اینکه از بیرون هم قابل دسترسی باشد، باید در فایل `sshd_config` سرور راه دور گزینه `GatewayPorts yes` فعال باشد.

---

## ۳. Dynamic Forward (`-D`)

### ساختار دستور
```bash
ssh -D [پورت_محلی] [کاربر]@[سرور_SSH]
```

### معنی اجزا
- `پورت_محلی`: پورتی روی کامپیوتر شما که به‌عنوان پروکسی SOCKS عمل می‌کند.
- `سرور_SSH`: سروری که ترافیک از آن عبور می‌کند.

### مثال: ساخت پروکسی SOCKS
```bash
ssh -D 1080 alice@server
```
- حالا در تنظیمات مرورگر (یا هر برنامه‌ای که از SOCKS پشتیبانی می‌کند)، پروکسی را روی `localhost:1080` از نوع SOCKS5 تنظیم کنید.
- تمام ترافیک مرورگر از تونل SSH عبور می‌کند و از دید وب‌سایت‌ها، IP سرور `server` دیده می‌شود.

### کاربرد
- دور زدن محدودیت‌های جغرافیایی (مثلاً دسترسی به سایتی که از کشور شما مسدود است).
- امن کردن ترافیک در شبکه‌های ناامن (مثل Wi-Fi عمومی).
- تست کردن موقعیت مکانی از دید سرور راه دور.

---

## گزینه‌های پرکاربرد SSH Tunneling

| گزینه | توضیح |
|---|---|
| `-N` | فقط تونل برقرار کن، دستور اجرا نکن |
| `-f` | بعد از احراز هویت، به پس‌زمینه برو |
| `-g` | اجازه دسترسی سایر میزبان‌ها به پورت محلی (پیش‌فرض فقط localhost) |
| `-C` | فشرده‌سازی داده‌ها (برای اتصالات کند مفید است) |
| `-T` | عدم تخصیص TTY (برای اسکریپت‌ها) |
| `-o ServerAliveInterval=60` | ارسال پیام keepalive هر ۶۰ ثانیه برای جلوگیری از قطعی |

---

## نکات امنیتی و محدودیت‌ها

- **تونل SSH امن است**، چون کل ترافیک داخل اتصال SSH رمزنگاری می‌شود.
- **در سرور راه دور، ممکن است محدودیت‌هایی اعمال شده باشد** (مثلاً `AllowTcpForwarding no` در `sshd_config`).
- **برای Local Forward، پورت محلی فقط به `localhost` گوش می‌دهد** مگر با `-g` آن را باز کنید (که ریسک امنیتی دارد).
- **هرگز تونل را روی پورت‌های حساس و در شبکه‌های عمومی باز نگذارید.**
- **برای بستن تونل، کافی است اتصال SSH را قطع کنید** (یا اگر پس‌زمینه است، پروسه را بکشید).

## ۱۲ب.۵ Fail2ban — محافظت خودکار در برابر Brute-force

### چگونه کار می‌کند — پل بین لاگ و فایروال

ا Fail2ban لاگ‌های سرویس‌ها (مثل `journalctl`/`/var/log/auth.log`) را زنده پایش می‌کند، الگوهای شکست احراز هویت را تشخیص می‌دهد، و به‌طور خودکار یک قانون فایروال (که در بخش ۱۲ با iptables/nftables دیدیم) برای مسدود کردن موقت آن IP اضافه می‌کند — این دقیقاً پلی بین **Logging** (بخش ۷) و **Firewall** (بخش ۱۲) است.

```ini
# /etc/fail2ban/jail.local
[sshd]
enabled = true
port = 2222
maxretry = 5
bantime = 3600
findtime = 600
```
ا `findtime` پنجره زمانی است که در آن `maxretry` تلاش ناموفق شمارش می‌شود؛ `bantime` مدت مسدودسازی است.

```bash
fail2ban-client status sshd
fail2ban-client set sshd unbanip 192.168.1.50
```

📌 نکته مهم: Fail2ban مکمل PAM `pam_faillock` (که در بخش ۱۱ دیدیم) است، نه جایگزین آن — `pam_faillock` حساب کاربری را قفل می‌کند، Fail2ban کل IP مهاجم را در سطح شبکه مسدود می‌کند؛ استفاده هم‌زمان از هر دو، دفاع در عمق واقعی است.
در ادامه، نسخه‌ی بازنویسی‌شده و کامل‌تر بخش **۱۲ب.۶ VPN — OpenVPN و WireGuard** و همچنین **۱۲ب.۷ خلاصه نکات کلیدی** را ارائه می‌دهم. این نسخه با توضیحات بیشتر، ساختار مرتب‌تر و زبان روان‌تر تنظیم شده است.

## ۱۲ب.۶ VPN — OpenVPN و WireGuard

ا **VPN (Virtual Private Network)** یک تونل رمزنگاری‌شده بین دو نقطه ایجاد می‌کند تا ترافیک شبکه از یک مسیر امن عبور کند. دو پیاده‌سازی متن‌باز و محبوب در لینوکس عبارتند از: **OpenVPN** (استاندارد قدیمی‌تر) و **WireGuard** (جایگزین مدرن).

---

### ا OpenVPN — استاندارد قدیمی‌تر و پیچیده‌تر

ا OpenVPN از **PKI (Public Key Infrastructure)** کامل استفاده می‌کند: یک **CA (Certificate Authority)** مرکزی، گواهی سرور، و گواهی جداگانه برای هر کلاینت. این ساختار امنیت بالا را تضمین می‌کند، اما راه‌اندازی و مدیریت آن پیچیده‌تر است.

#### مراحل ساخت PKI با EasyRSA

```bash

#i ۱. مقداردهی اولیه به پوشه PKI
easyrsa init-pki

# ۲. ساخت CA (مرجع صدور گواهی) — در اینجا بدون رمز عبور ساخته می‌شود
easyrsa build-ca nopass

# ۳. ساخت درخواست گواهی برای سرور (بدون رمز عبور)
easyrsa gen-req server nopass

# ۴. امضای درخواست سرور توسط CA
easyrsa sign-req server server
```

> 🔹 برای هر کلاینت نیز باید همین مراحل (`gen-req` و `sign-req`) تکرار شود.

#### نمونه فایل پیکربندی سرور (`/etc/openvpn/server.conf`)

```bash
port 1194                     # پورت پیش‌فرض OpenVPN
proto udp                     # پروتکل UDP (سریع‌تر از TCP)
dev tun                       # استفاده از دستگاه TUN (لایه ۳)
server 10.8.0.0 255.255.255.0 # محدوده IP تونل
push "redirect-gateway def1 bypass-dhcp"  # هدایت کل ترافیک کلاینت از VPN
```

- ا  `dev tun` یک رابط مجازی نقطه‌به‌نقطه ایجاد می‌کند.
- ا `push "redirect-gateway ..."` به کلاینت می‌گوید تمام ترافیک خود را از VPN عبور دهد (مناسب برای دسترسی امن به اینترنت).
- پس از راه‌اندازی، سرویس را با `systemctl start openvpn@server` فعال کنید.

> ⚠️ا  OpenVPN به دلیل استفاده از PKI و کتابخانه‌های رمزنگاری، سربار پردازشی بیشتری نسبت به WireGuard دارد.

---

### ا WireGuard — جایگزین مدرن، ساده‌تر و سریع‌تر

ا WireGuard به‌جای PKI کامل، فقط از **جفت‌کلید ساده (Public/Private Key)** استفاده می‌کند. هر دو طرف (سرور و کلاینت) یک جفت‌کلید دارند و کلیدهای عمومی با هم مبادله می‌شوند. به‌دلیل پیاده‌سازی در **فضای کرنل**، کارایی بسیار بالاتری دارد و برای سیستم‌های Embedded و سرورهای پرترافیک ایده‌آل است.

#### تولید کلیدها

```bash
#i تولید کلید خصوصی و عمومی (روی سرور و هر کلاینت جداگانه انجام می‌شود)
wg genkey | tee privatekey | wg pubkey > publickey
```

#### نمونه فایل پیکربندی سرور (`/etc/wireguard/wg0.conf`)

```ini
[Interface]
PrivateKey = <server_private_key>
Address = 10.0.0.1/24
ListenPort = 51820

[Peer]
PublicKey = <client_public_key>
AllowedIPs = 10.0.0.2/32
```

- `Address` آدرس IP سرور در شبکه تونل است.
- `ListenPort` پورت UDP که WireGuard به آن گوش می‌دهد (پیش‌فرض 51820).
- `[Peer]` برای هر کلاینت تکرار می‌شود؛ `AllowedIPs` مشخص می‌کند چه ترافیکی از این Peer عبور کند. برای کلاینت معمولاً `10.0.0.2/32` قرار می‌گیرد.

#### فعال‌سازی و بررسی

```bash
wg-quick up wg0      # بالا آوردن تونل
wg show              # نمایش وضعیت تونل‌ها و Peer ها
```

> 🔹 برای اجرای خودکار در بوت: `systemctl enable wg-quick@wg0`

#### فایل پیکربندی کلاینت (نمونه)

```ini
[Interface]
PrivateKey = <client_private_key>
Address = 10.0.0.2/24
DNS = 8.8.8.8

[Peer]
PublicKey = <server_public_key>
Endpoint = server_ip:51820
AllowedIPs = 0.0.0.0/0, ::/0
PersistentKeepalive = 25
```

- `AllowedIPs = 0.0.0.0/0` یعنی تمام ترافیک کلاینت از VPN عبور کند.
- `PersistentKeepalive` برای عبور از NAT مفید است.

## ۱۲ب.۷ خلاصه نکات کلیدی برای آزمون

- ا **`PermitRootLogin no`** و **`PasswordAuthentication no`** دو تنظیم پایه و اجباری برای هر سرور Production هستند. اولی ورود مستقیم root را ممنوع می‌کند و دومی احراز هویت با رمز عبور را غیرفعال می‌کند تا فقط کلید SSH مجاز باشد.
- **تغییر پورت SSH** (مثلاً از ۲۲ به ۲۲۲۲) فقط **نویز اسکن** را کاهش می‌دهد و یک لایه امنیتی واقعی محسوب نمی‌شود (Security through Obscurity). مهاجم با اسکن کامل پورت‌ها می‌تواند آن را پیدا کند.
- ا **Fail2ban** پلی بین **لاگ‌ها** (بخش ۷) و **فایروال** (بخش ۱۲) است: با خواندن لاگ‌ها، IPهای مهاجم را شناسایی و به‌طور خودکار در فایروال مسدود می‌کند. این مکمل **`pam_faillock`** (بخش ۱۱) است، نه جایگزین آن. `pam_faillock` در سطح PAM قفل حساب را فعال می‌کند، در حالی که Fail2ban در سطح شبکه IP را بلاک می‌کند.
- ا **WireGuard** نسبت به OpenVPN **ساده‌تر** (بدون نیاز به PKI کامل) و **سریع‌تر** (پیاده‌سازی در کرنل) است. برای راه‌اندازی سریع و کارایی بالا توصیه می‌شود، در حالی که OpenVPN برای محیط‌هایی با نیاز به سازگاری بیشتر یا مدیریت متمرکز گواهی‌ها مناسب‌تر است.
