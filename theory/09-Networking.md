# بخش ۹: Networking (شبکه)


## ۹.۱ مدل OSI — زبان مشترک برای صحبت درباره شبکه

### چرا به یک مدل لایه‌ای نیاز داریم؟

ارتباط بین دو کامپیوتر روی شبکه، در واقع یک فرآیند بسیار پیچیده است: باید سیگنال الکتریکی/نوری روی کابل منتقل شود، باید دستگاه‌های میانی (سوییچ، روتر) بسته را به مقصد درست هدایت کنند، باید تضمین شود داده کامل و بدون خطا برسد، و در نهایت باید برنامه‌ای که این داده را می‌فرستد و برنامه‌ای که آن را دریافت می‌کند، معنای مشترکی از آن داده داشته باشند. اگر این همه پیچیدگی در یک لایه واحد مدیریت می‌شد، طراحی، عیب‌یابی، و توسعه شبکه تقریباً غیرممکن می‌بود.

**مدل OSI (Open Systems Interconnection)** این پیچیدگی را به **۷ لایه مجزا** تقسیم می‌کند، که هر لایه فقط مسئول یک جنبه خاص است و با لایه‌های بالا/پایین خودش از طریق یک رابط استاندارد صحبت می‌کند — دقیقاً همان فلسفه‌ای که در بخش ۳ با VFS دیدیم (یک لایه انتزاعی که پیچیدگی زیرین را از لایه بالاتر پنهان می‌کند).

| لایه | نام | مثال |
|---|---|---|
| ۷ | Application | HTTP, DNS, SMTP |
| ۶ | Presentation | رمزنگاری TLS، فرمت داده |
| ۵ | Session | مدیریت نشست‌های ارتباطی |
| ۴ | Transport | TCP, UDP |
| ۳ | Network | IP، مسیریابی |
| ۲ | Data Link | Ethernet، MAC Address، سوییچ |
| ۱ | Physical | کابل، سیگنال الکتریکی/نوری |

📌 در دنیای عملی لینوکس، بیشتر توجه روی لایه‌های ۲ (Data Link)، ۳ (Network)، و ۴ (Transport) است — چون این‌ها جایی هستند که اکثر پیکربندی و عیب‌یابی روزمره رخ می‌دهد. مدل عملی‌تر TCP/IP این ۷ لایه را در ۴ لایه ساده‌تر خلاصه می‌کند (Network Access، Internet، Transport، Application) اما درک مفهومی ۷ لایه OSI برای عیب‌یابی دقیق (کدام لایه دقیقاً مشکل دارد؟) بسیار ارزشمند است.

## ۹.۲ لایه ۲ — Data Link: MAC Address و Ethernet

### ا MAC Address چیست؟

هر کارت شبکه فیزیکی (یا مجازی) یک شناسه یکتای ۴۸ بیتی به نام **MAC Address (Media Access Control Address)** دارد که (تئوریاً) در سطح جهانی یکتاست و توسط سازنده کارت شبکه در کارخانه تعیین می‌شود. فرمت آن شش گروه دو رقمی هگزادسیمال است، مثل `00:1A:2B:3C:4D:5E`.

```bash
ip link show <" eth0 ">
```
خط `link/ether` در خروجی، MAC Address آن اینترفیس را نشان می‌دهد.

### چرا هم MAC Address و هم IP Address داریم؟

این یک سوال بنیادین است: MAC Address برای ارتباط **در همان شبکه محلی (Local Segment)** استفاده می‌شود — وقتی دو دستگاه مستقیماً روی همان سوییچ هستند، سوییچ بسته‌ها را بر اساس MAC Address به پورت صحیح هدایت می‌کند. اما MAC Address هیچ ساختار سلسله‌مراتبی جغرافیایی ندارد (نمی‌توان از آن فهمید یک دستگاه در کدام شبکه/کشور است)، پس برای مسیریابی بین شبکه‌های مختلف (که اینترنت از میلیون‌ها آن تشکیل شده) مناسب نیست — این دقیقاً کاری است که **IP Address** (لایه ۳) انجام می‌دهد.

### ا ARP — پل ارتباطی بین IP و MAC

وقتی کامپیوتر شما می‌خواهد به یک IP در همان شبکه محلی (مثلاً `192.168.1.1`) بسته بفرستد، باید بداند MAC Address متناظر آن IP چیست (چون در سطح فیزیکی، سوییچ بر اساس MAC کار می‌کند، نه IP). **ARP (Address Resolution Protocol)** این ترجمه را انجام می‌دهد: کامپیوتر یک پیام Broadcast می‌فرستد («کی IP آدرس 192.168.1.1 است؟»)، و دستگاهی که آن IP را دارد، با MAC Address خودش پاسخ می‌دهد.

```bash
ip neigh show
```
نمایش **جدول ARP** (که در لینوکس مدرن Neighbor Table نامیده می‌شود) — نگاشت IP به MAC که اخیراً resolve شده، برای جلوگیری از تکرار درخواست ARP برای هر بسته.

```bash
arping -c 3 192.168.1.1
```
ارسال دستی درخواست ARP برای تست مستقیم اتصال لایه ۲ به یک دستگاه خاص — مفید وقتی `ping` (که لایه ۳ است) کار نمی‌کند و می‌خواهید بفهمید آیا مشکل حتی از لایه پایین‌تر (فیزیکی/لینک) شروع می‌شود.

## ۹.۳ لایه ۳ —  IP Addressing و Subnetting

### ا IPv4 — ساختار آدرس

یک آدرس IPv4 از ۳۲ بیت تشکیل شده که معمولاً در قالب چهار عدد ده‌دهی (هرکدام ۰ تا ۲۵۵، معادل ۸ بیت) با نقطه جدا نمایش داده می‌شود: `192.168.1.10`.

### ا CIDR — چگونه مشخص می‌کنیم یک آدرس به کدام «شبکه» تعلق دارد

یک آدرس IP به‌تنهایی کافی نیست — باید بدانیم چه بخشی از این آدرس «شبکه» (Network) و چه بخشی «میزبان» (Host) را مشخص می‌کند. **CIDR (Classless Inter-Domain Routing)** این را با یک عدد بعد از `/` نشان می‌دهد: `192.168.1.0/24` یعنی ۲۴ بیت اول (سه گروه اول) بخش شبکه است، و ۸ بیت باقی‌مانده (گروه چهارم) برای شماره‌گذاری میزبان‌های داخل آن شبکه استفاده می‌شود — یعنی این شبکه می‌تواند میزبان‌هایی از `192.168.1.0` تا `192.168.1.255` داشته باشد (۲۵۶ آدرس، که دو تای آن — اولی برای Network Address و آخری برای Broadcast Address — رزرو هستند، پس عملاً ۲۵۴ آدرس قابل‌استفاده).

### ا Subnetting — تقسیم یک شبکه بزرگ به شبکه‌های کوچک‌تر

فرض کنید یک سازمان یک بلوک بزرگ IP (مثلاً `10.0.0.0/16`، معادل ۶۵۵۳۶ آدرس) دارد اما می‌خواهد آن را بین چند بخش مختلف (بخش مالی، بخش فنی، بخش مهمان) تقسیم کند، طوری که ترافیک هر بخش از بخش دیگر جدا باشد. **Subnetting** یعنی گرفتن این بلوک بزرگ و تقسیم آن به بلوک‌های کوچک‌تر با تغییر تعداد بیت‌های Network:

```
10.0.0.0/16    ← بلوک اصلی (65536 آدرس)
    ↓ تقسیم به subnet های /24 (هرکدام 256 آدرس)
10.0.1.0/24    ← بخش مالی
10.0.2.0/24    ← بخش فنی
10.0.3.0/24    ← بخش مهمان
```

هرچقدر عدد بعد از `/` بزرگ‌تر باشد، بیت‌های بیشتری صرف Network شده، پس آدرس‌های کمتری برای Host باقی می‌ماند (شبکه کوچک‌تر). محاسبه سریع: تعداد آدرس‌های یک subnet برابر `2^(32 - prefix)` است — مثلاً `/24` یعنی `2^8 = 256` آدرس، `/28` یعنی `2^4 = 16` آدرس.

📌 این محاسبات subnetting یکی از کلاسیک‌ترین و پرتکرارترین بخش‌های آزمون LPIC هستند — تسلط عملی روی تبدیل بین prefix (`/24`) و Subnet Mask (`255.255.255.0`) و محاسبه بازه آدرس‌های هر subnet ضروری است.

```bash
ipcalc 192.168.1.0/24
```
ا `ipcalc` (اگر نصب باشد) این محاسبات را خودکار انجام می‌دهد: Network Address، Broadcast Address، اولین و آخرین آدرس قابل‌استفاده، تعداد کل میزبان.

### ا IPv6 — نسل بعدی آدرس‌دهی

ا IPv6 از ۱۲۸ بیت استفاده می‌کند (در برابر ۳۲ بیت IPv4)، که فضای آدرس‌دهی به‌طور غیرقابل‌تصوری بزرگ‌تری فراهم می‌کند — این برای حل مشکل تمام‌شدن آدرس‌های IPv4 (که سال‌هاست جهان با آن دست‌به‌گریبان است) طراحی شده. فرمت آن هشت گروه چهار رقمی هگزادسیمال با `:` جدا است: `2001:0db8:85a3:0000:0000:8a2e:0370:7334`.

آدرس‌های خاص IPv6:
- ا `::1` معادل `127.0.0.1` (loopback)
- ا `fe80::/10` — **Link-Local**: آدرسی که هر اینترفیس خودکار می‌گیرد، فقط برای ارتباط در همان segment محلی معتبر است (مشابه مفهومی APIPA در IPv4 اما با کاربرد رسمی و گسترده‌تر)
- ا `fc00::/7` — **Unique Local Address**: معادل IPv6 آدرس‌های خصوصی IPv4 (مثل `192.168.x.x`)

```bash
ip -6 addr show
ping6 -c 3 2001:4860:4860::8888
```

## ۹.۴ لایه ۴ — Transport: TCP در برابر UDP

### تفاوت بنیادین — قابلیت‌اطمینان در برابر سرعت

ا **TCP (Transmission Control Protocol)** یک پروتکل **Connection-Oriented** (اتصال‌گرا) است: قبل از ارسال داده واقعی، یک «دست‌دهی سه‌مرحله‌ای» (Three-Way Handshake — `SYN`, `SYN-ACK`, `ACK`) بین دو طرف برقرار می‌شود تا یک اتصال رسمی تایید شود. TCP تضمین می‌کند بسته‌ها به ترتیب صحیح برسند و اگر بسته‌ای گم شود، دوباره ارسال شود — این قابلیت‌اطمینان با هزینه‌ای از سربار و تاخیر بیشتر همراه است. اکثر پروتکل‌های حیاتی که نیاز به تحویل کامل و صحیح دارند (HTTP، SSH، SMTP، پایگاه‌داده) از TCP استفاده می‌کنند.

ا **UDP (User Datagram Protocol)** یک پروتکل **Connectionless** (بدون اتصال) است: هیچ دست‌دهی اولیه‌ای وجود ندارد، هیچ تضمینی برای رسیدن یا ترتیب بسته‌ها داده نمی‌شود — فقط بسته فرستاده می‌شود و امید می‌رود که برسد. این سادگی باعث سرعت و سربار بسیار کمتر می‌شود، مناسب برای کاربردهایی که سرعت مهم‌تر از تضمین کامل تحویل است (استریم صوت/ویدیوی زنده، DNS query های ساده، بازی‌های آنلاین).

### پورت‌ها — چگونه چند سرویس روی یک IP کار می‌کنند؟

یک سرور ممکن است هم‌زمان یک وب‌سرور، یک سرور ایمیل، و یک سرور SSH روی همان IP اجرا کند — **پورت (Port)** یک عدد ۱۶ بیتی (۰ تا ۶۵۵۳۵) است که مشخص می‌کند بسته دقیقاً برای کدام سرویس روی آن دستگاه است. ترکیب IP + پورت را **Socket** می‌نامند.

پورت‌های معروف (Well-Known Ports، معمولاً زیر ۱۰۲۴): `22` (SSH)، `80` (HTTP)، `443` (HTTPS)، `53` (DNS).

```bash
ss -tulpn
```
نمایش تمام پورت‌های در حال گوش‌دادن (Listening) روی سیستم؛ `-t` (TCP)، `-u` (UDP)، `-l` (فقط Listening، نه اتصالات فعال)، `-p` (نمایش نام برنامه مالک هر پورت)، `-n` (نمایش عددی به‌جای تلاش برای resolve نام).

## ۹.۵ پیکربندی اینترفیس‌های شبکه با iproute2

### چرا ip به‌جای ifconfig؟

ابزار `ifconfig` (و `route`, `arp`) قدیمی‌تر و از پروژه‌ای هستند که سال‌هاست دیگر به‌طور فعال توسعه داده نمی‌شود؛ مجموعه ابزار **iproute2** (دستور واحد `ip`) جانشین مدرن و کامل‌تر آن است که در تمام توزیع‌های امروزی استاندارد است.

```bash
ip addr show                              # نمایش تمام IP ها (معادل ifconfig)
ip addr add 192.168.1.10/24 dev eth0        # افزودن IP (موقت)
ip addr del 192.168.1.10/24 dev eth0

ip link show                                # وضعیت اینترفیس‌ها (up/down)
ip link set eth0 up
ip link set eth0 down
ip link set eth0 mtu 9000                    # تنظیم MTU (حداکثر اندازه بسته — 9000 برای Jumbo Frame)

ip route show                                # جدول مسیریابی (معادل route)
ip route add 10.0.0.0/24 via 192.168.1.1
ip route add default via 192.168.1.1          # مسیر پیش‌فرض (Gateway)
```

⚠️ نکته حیاتی: تغییرات با `ip` **موقتی** هستند و با ریبوت از بین می‌روند. برای دائمی کردن، باید از ابزار مدیریت شبکه توزیع (NetworkManager با `nmcli`، netplan، یا `/etc/network/interfaces`) استفاده کرد.

### ابزارهای مدیریت دائمی — NetworkManager و systemd-networkd

ا **NetworkManager** (با ابزار خط‌فرمان `nmcli`) رایج‌ترین سیستم مدیریت شبکه در توزیع‌های دسکتاپ و بسیاری سرورهای RHEL/Fedora است — طراحی شده برای مدیریت پویا و آسان (مناسب محیط‌هایی که شبکه ممکن است تغییر کند، مثل لپ‌تاپ که بین Wi-Fi های مختلف جابه‌جا می‌شود).

```bash
nmcli connection show
nmcli connection add type ethernet con-name eth0-static ifname eth0 ip4 192.168.1.10/24 gw4 192.168.1.1
nmcli connection modify eth0-static ipv4.dns "8.8.8.8 1.1.1.1"
nmcli connection up eth0-static
```

ا **systemd-networkd** یک جایگزین سبک‌تر و ساده‌تر است که برای سرورها (با پیکربندی شبکه ثابت و ساده، بدون نیاز به مدیریت پویا) طراحی شده — بخشی از پروژه systemd، با فایل‌های تنظیمات متنی ساده:

```ini
# /etc/systemd/network/10-eth0.network
[Match]
Name=eth0

[Network]
Address=192.168.1.10/24
Gateway=192.168.1.1
DNS=8.8.8.8
```

```bash
systemctl enable --now systemd-networkd
networkctl status
```

## ۹.۶ ا Bonding و Bridge — ترکیب و اتصال اینترفیس‌ها

### ا Bonding — تجمیع چند کارت شبکه فیزیکی

ا **Bonding** (که با جزئیات کامل در سناریوهای این بخش می‌بینیم) چند اینترفیس فیزیکی را به‌عنوان یک اینترفیس منطقی واحد نشان می‌دهد، برای **افزونگی** (اگر یکی خراب شود، دیگری جایگزین می‌شود) یا **افزایش پهنای باند** (بسته به mode انتخابی).

```bash
#nmcli
nmcli connection add type bond con-name bond0 ifname bond0 mode active-backup
nmcli connection add type ethernet con-name bond0-eth0 ifname eth0 master bond0
nmcli connection add type ethernet con-name bond0-eth1 ifname eth1 master bond0
```

مهم‌ترین mode ها: `active-backup` (ساده، فقط یکی در هر لحظه فعال، سایرین آماده‌باش)، `balance-rr` (توزیع دوره‌ای بسته‌ها بین همه اعضا، برای افزایش پهنای باند اما نیازمند پشتیبانی سوییچ از LACP).

### ا Bridge — سوییچ نرم‌افزاری

ا **Bridge** یک سوییچ لایه ۲ نرم‌افزاری است که چند اینترفیس (فیزیکی یا مجازی) را به یک شبکه واحد متصل می‌کند — بسیار رایج در محیط‌های مجازی‌سازی (KVM/QEMU)، جایی که ماشین‌های مجازی متعدد باید به شبکه فیزیکی میزبان دسترسی داشته باشند، انگار مستقیماً به همان سوییچ فیزیکی متصل‌اند.

```bash
ip link add br0 type bridge
ip link set eth0 master br0
ip link set br0 up
```

### ا VLAN — تقسیم منطقی یک شبکه فیزیکی

ا **VLAN (Virtual LAN)** به شما اجازه می‌دهد یک زیرساخت فیزیکی واحد (یک سوییچ) را به چند شبکه منطقی کاملاً مجزا (که ترافیک هرکدام از دیگری ایزوله است) تقسیم کنید، بدون نیاز به سیم‌کشی جداگانه فیزیکی برای هر بخش. هر VLAN با یک شماره (Tag) شناسایی می‌شود.

```bash
ip link add link eth0 name eth0.100 type vlan id 100
ip addr add 192.168.100.1/24 dev eth0.100
ip link set eth0.100 up
```
این دستورات یک اینترفیس مجازی جدید (`eth0.100`) می‌سازند که ترافیک آن با تگ VLAN شماره ۱۰۰ نشانه‌گذاری می‌شود — سوییچ‌های فیزیکی که از VLAN پشتیبانی می‌کنند (Managed Switch)، بر اساس این تگ، ترافیک هر VLAN را از بقیه جدا نگه می‌دارند.

## ۹.۷ ابزارهای عیب‌یابی شبکه — جعبه‌ابزار کامل

### ابزارهای تست اتصال پایه

```bash
ping -c 4 8.8.8.8              # تست اتصال لایه 3 (آیا مقصد پاسخ می‌دهد؟)
traceroute 8.8.8.8               # مسیر کامل بسته تا مقصد، هاپ به هاپ
mtr 8.8.8.8                       # ترکیب زنده ping + traceroute، بسیار مفید برای دیدن packet loss در یک هاپ خاص
```

### ابزارهای بررسی وضعیت شبکه محلی

```bash
ethtool eth0
```
نمایش اطلاعات سطح پایین سخت‌افزاری کارت شبکه: سرعت لینک (مثلاً ۱ گیگابیت)، حالت Duplex (Full/Half)، و این‌که آیا لینک فیزیکی متصل است یا نه — اولین قدم عیب‌یابی وقتی مشکوکید مشکل از خود کابل/کارت شبکه است.

```bash
ss -s
```
خلاصه آماری کلی از تمام اتصالات فعال سیستم (چند TCP، چند UDP، چند در وضعیت TIME_WAIT).

### ابزار قدرتمند تحلیل بسته — tcpdump

```bash
tcpdump -i eth0 port 443
tcpdump -i eth0 host 192.168.1.5 and port 22 -w capture.pcap
```
ا `tcpdump` محتوای واقعی بسته‌های عبوری از یک اینترفیس را capture می‌کند — دقیق‌ترین سطح ممکن برای عیب‌یابی («آیا بسته اصلاً به این اینترفیس رسید؟»)؛ `-w` خروجی را در یک فایل باینری برای تحلیل عمیق‌تر بعدی (مثلاً با Wireshark) ذخیره می‌کند.

### ا nmap — اسکن شبکه و پورت

```bash
nmap -sT 192.168.1.0/24            # اسکن TCP کامل تمام دستگاه‌های یک subnet
nmap -p 22,80,443 192.168.1.10       # اسکن پورت‌های خاص روی یک هدف
nmap -sV 192.168.1.10                  # تلاش برای شناسایی نسخه سرویس‌های در حال اجرا روی پورت‌های باز
```
⚠️ اسکن پورت روی شبکه‌ای که مالک آن نیستید (یا مجوز صریح ندارید) می‌تواند از نظر قانونی مشکل‌ساز باشد؛ `nmap` باید فقط روی زیرساخت خودتان یا با اجازه صریح استفاده شود.

## ۹.۸ خلاصه نکات کلیدی برای آزمون

- مدل OSI ۷ لایه (حفظ ترتیب: Physical, Data Link, Network, Transport, Session, Presentation, Application)؛ لایه ۲ (MAC/Ethernet)، لایه ۳ (IP)، لایه ۴ (TCP/UDP) بیشترین اهمیت عملی را دارند
- ا ARP پل بین IP (لایه ۳) و MAC (لایه ۲) در یک شبکه محلی است
- محاسبات CIDR/Subnetting (تبدیل prefix به تعداد آدرس، تشخیص Network/Broadcast Address) باید کاملاً مسلط باشد
- تفاوت بنیادین TCP (قابل‌اعتماد، connection-oriented، هزینه سربار بیشتر) و UDP (سریع، بدون تضمین، سربار کمتر)
- ا `ip` (iproute2) ابزار مدرن استاندارد است؛ تغییرات آن موقتی هستند مگر با NetworkManager/systemd-networkd/netplan دائمی شوند
- ا Bonding افزونگی/کارایی چند کارت فیزیکی را ترکیب می‌کند؛ Bridge یک سوییچ نرم‌افزاری لایه ۲ است؛ VLAN یک زیرساخت فیزیکی را به چند شبکه منطقی مجزا تقسیم می‌کند
- ترتیب استاندارد عیب‌یابی شبکه: Link (`ip link`) → IP (`ip addr`) → Gateway (`ping`) → Routing (`ip route`) → DNS → Port/Service
- ا `mtr` ترکیب زنده ping+traceroute برای تشخیص دقیق محل packet loss در مسیر است
